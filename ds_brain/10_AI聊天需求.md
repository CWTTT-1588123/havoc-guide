## 一、目标
给网站加一个 **AI 聊天智能体**：
- **入口**：点击右下角 **Q 版人物（桌宠）** 打开对话窗口（和桌宠"说话"）。
- **定位**：站点**专属对话 AI**（有网站人设），主要回答**本站内容相关**的问题（英雄/符文/装备/胜率/出装推荐等），也支持**日常闲聊**。
- **体验**：像聊天一样一问一答；回答尽量**基于网站真实数据**，不编造。

## 二、功能需求（用户视角）
| # | 需求 | 说明 |
|---|---|---|
| 1 | **点桌宠开聊** | 点 Q 版人物 → 弹出聊天窗（保留点击说语录？→ 改成：单击开聊、气泡语录仍可出现，见交互设计） |
| 2 | **一问一答** | 输入框 + 发送；AI 回复；像微信/B站私信那样气泡式对话 |
| 3 | **站点知识问答** | "亚索带什么符文""胜率最高英雄""XX怎么出装""棱彩符文有哪些"等，**用网站真实数据回答**（引用胜率/场次等） |
| 4 | **日常闲聊** | "你好""你是谁""讲个笑话"等，友好闲聊 |
| 5 | **AI 人设** | 自称"海克斯小助手"之类，说话风格可爱/简洁，符合网站调性 |
| 6 | **上下文记忆**（可选） | 同一会话内记得刚才聊的内容（多轮对话） |
| 7 | **安全与成本** | API Key **只在服务器**，前端不暴露；限制消息长度/频率防刷费用 |

## 三、技术方案（初版，简单可上线）

### 3.1 大模型选择（待用户定）
国内易用、便宜、效果好的候选：
| 服务 | 说明 |
|---|---|
| **DeepSeek**（推荐） | 便宜（约¥0.5-2/百万token）、中文好、OpenAI 兼容接口、注册送额度 |
| 通义千问 Qwen | 阿里系，便宜，有免费额度 |
| 智谱 GLM / Kimi | 也可 |

**决策点1**：选哪家？（默认建议 **DeepSeek**）

### 3.2 后端（FastAPI，不动前端框架结构）
- 新增 `POST /api/chat`：
  - 入参：`{messages: [{role, content}, ...]}`（对话历史）
  - 服务端把 **API Key**（放 `.env`）发给大模型，**Key 不出服务器**
  - 出参：`{reply: "..."}`
- **知识注入（简化版 RAG）**：用户问题来了之后：
  1. 用关键词（英雄名/符文名/装备名）从 `stats.json` 检索相关数据（复用现有 `/api/*` 的数据结构）；
  2. 把"该英雄胜率/最优符文/出装/克制"等**真实数据拼进 system prompt**；
  3. 要求 AI **只依据这些数据回答**，数据没有的就说不知道。
- **人设**：system prompt 写死"你是海克斯大乱斗攻略站的 AI 助手…"。
- **限流/长度**：每次最多 N 条历史、单条 ≤ 500 字；可加简单频率限制。

### 3.3 前端（Vue 组件）
- 新增 `ChatBot.vue`：聊天窗（气泡列表 + 输入框 + 发送）。
- `Pet.vue` 点击事件 → 打开 `ChatBot`（`state.chatOpen`）。
- 发送 → `fetch('/api/chat')` → 显示回复；**"思考中…"** loading 态。
- 保留桌宠气泡语录（点击时**先出语录气泡，同时打开聊天窗**，或二者选一——决策点2）。

### 3.4 决策点（✅ 已拍板 2026-09-04）
| 决策点 | 拍板 |
|---|---|
| 1. 大模型 | **DeepSeek**（deepseek-chat） |
| 2. 点桌宠行为 | **直接打开聊天窗**；语录气泡**不再靠点击**，改为**切换主/子页面或点击网站标题时随机出现** |
| 3. 回复方式 | **先一次性返回**，后续再加"逐字流式" |
| 4. 数据检索 | **检索注入**（关键词从 stats.json 检索英雄/符文/装备真实数据注入 prompt） |
| 5. 对话记忆 | **多轮**（带最近几条历史，服务端保存会话上下文） |
| 6. 登录 | **免登录可聊**，但加**频率限制**（防刷费用） |

**目标效果**：像跟 DeepSeek 官方聊天一样**智能** + **自带人设**（海克斯大乱斗攻略站专属 AI 助手）+ **有一定记忆**（多轮上下文）+ 对**网站内容回答非常准确**（检索注入真实数据 + 强约束"只依据提供的数据回答"）。

## 四、界面设计（初版）
- 聊天窗：右下角、与桌宠同位或居中弹出；`400px` 宽、`60vh` 高圆角卡片。
- 气泡：用户右侧蓝色、AI 左侧白/深色；头像用小 Q 版头像。
- 顶部：AI 名字 + "海克斯小助手" + 关闭按钮。
- 底部：输入框 + 发送按钮（Enter 发送）。
- 浅色/深色模式都要适配（用现有 CSS 变量）。

## 五、分步实施计划（给用户学习用，一步一步来）
1. **准备**：注册大模型、拿 API Key、充值/确认额度（最小 ¥10 够测很久）。
2. **后端**：`webapp.py` 加 `/api/chat` + `.env` 存 Key + 检索注入 + 限流；本地 curl 测试。
3. **前端**：`ChatBot.vue` + `Pet.vue` 点击接入 + `store.chatOpen`；浏览器测试。
4. **打磨**：多轮记忆、人设优化、错误处理（超时/Key 失效提示）。
5. **上线**：服务器 `.env` 配 Key、部署重启；浏览器/手机测试。
6. （可选升级）流式回复、语音、分享。

## 六、注意/风险
- **API Key 绝不放前端/不提交 git**（只放服务器 `.env`，`.env` 已在 gitignore）。
- **成本控制**：限流 + 限长；大模型按 token 计费。
- **回答质量**：AI 可能"编数据"——必须用系统提示词强约束"只依据提供的数据回答"。
- **国内合规**：内容用系统提示词约束（不涉政/不违规），必要时加敏感词过滤。
