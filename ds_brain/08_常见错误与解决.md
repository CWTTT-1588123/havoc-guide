# 常见错误与解决（ds_brain 08）

> 本文件**重点记录项目过程中踩过的一切坑 + 怎么解决**，供回顾/接手参考。
> 每次遇到新错误 + 解决，**务必追加到这里**。

---

## 一、部署 / 服务器类

| 错误现象 | 原因 | 解决办法 |
|---|---|---|
| 公网访问 `ERR_CONNECTION_REFUSED` | uvicorn 用了 `--host 127.0.0.1`，只监听本机 | uvicorn 必须 **`--host 0.0.0.0`**（走 Nginx 时还可改回 127.0.0.1） |
| 登录态刷新**随机掉线** | `--workers 2`：用户表在内存，各进程不共享 | 改 **`--workers 1`**（单进程，内存一致） |
| apt 安装时弹 **"Daemons using outdated libraries"**（Ubuntu needrestart） | 装完包系统问哪些服务要重启 | 选 **`<Ok>`**；脚本里加 `DEBIAN_FRONTEND=noninteractive` + `NEEDRESTART_MODE=a` 免交互 |
| `tar.exe` **Access is denied**（沙箱拦） | tar.exe 被沙箱策略拦 | 改用 **Python `tarfile`** 打包 |
| `pip install` **WinError 5 / EPERM**（沙箱拦，写到系统 site-packages） | pip 写系统目录被拦 | 用 node 下载 **wheel** + `pip install --target <工作区>` + 设 PYTHONPATH |
| scp 报 **"dest open /root/...：No such file or directory"** | 部署路径写错（不是 `/root/havoc_guide`） | 服务器解压后在 **`/root`** 根目录，前端在 **`/root/static/`**、后端在 `/root/webapp.py` |

## 二、登录 / 认证类

| 错误现象 | 原因 | 解决办法 |
|---|---|---|
| **重新抓包时 mitmweb 起不来**：`ModuleNotFoundError: h11 / bcrypt` 或 `No module named pip` | 爬虫 venv 曾清理依赖/丢 pip | `python -m ensurepip --upgrade` 先修 pip，再 `pip install -r wegame-capture\requirements.txt`（沙箱下 TMP 指到工作区 + 全权限） |
| **信任 mitmproxy 证书时 PowerShell 卡死**（`.NET X509Store.Add` 无响应超时） | Add 触发证书安装确认对话框，无人点 | 改用 **`certutil -user -addstore Root <cer>`**（删除用 `-delstore Root mitmproxy`），不弹窗 |
| **爬虫 json.load 崩**：`JSONDecodeError: Unexpected UTF-8 BOM` | `hidden_players.json` 被 PowerShell/记事本写过带 BOM | 读改用 **`encoding="utf-8-sig"`**；顺手把 BOM 文件重写为无 BOM |
| 登录失败但**站点没重启** | 前端 `index.html` 改动**不需重启**（刷新即生效）；但 **`webapp.py` 改完必须重启** | 改前端刷新即可；改后端 `systemctl restart havoc-guide` |
| 忘记/不确定 root 密码 | 之前混乱 | 阿里云控制台 → 实例 → 更多 → 密码/密钥 → **重置实例密码** → 重启实例 |
| 改了 `users.json` 人名**乱码** | PowerShell `ConvertTo-Json` 会破坏中文 | 用 **Python** 写 JSON（`json.dump(ensure_ascii=False)`），或 Unicode 转义 `\u7ba1...` |
| 给已有账号加 token 后**旧登录失效** | 用单 token 字段 | 改用 **tokens 列表**（多端会话，登录只追加不互踢） |
| 密码哈希**进 repo 被公开** | users.json 含 phash，误 commit | 绝不提交；仓库设私有；改密码 |

## 三、前端 / 视觉类

| 错误现象 | 原因 | 解决办法 |
|---|---|---|
| **浏览器自动填充把登录邮箱填进搜索框** | 搜索框是普通文本输入、没 `autocomplete` | 搜索框加 **`autocomplete="off"`** + `type=text` + **`readonly`(onfocus 解除)** + 页面加载清空 |
| 深色模式**文字看不清**（黑字黑底） | 硬编码 `color:#111` 不随主题 | 加 `html.dark .xxx { color:#e8edf8 }` 覆盖 |
| 登录弹窗**透明** | `--panel2` 半透明(0.48) | 登录卡改**纯白底** `#fff` |
| 密码框出现**两个眼睛** | 浏览器自带"显示密码"图标 + 自建的眼睛 | CSS 隐藏 `input[type=password]::-ms-reveal` 等 |
| 顶部三个登录标签**挤在一行** | 卡片太窄 | 加宽卡片 + `white-space:nowrap` + 缩小 gap |
| 深色模式**自定义背景被黑色盖住**（用户上传的浅色背景在深色下） | 浅色背景配深色字不协调 | 深色模式**用深色预设背景**；浅色模式才用自定义；删除"上传图片背景" |
| **手机上管理员重置密码不弹输入框**（只弹提示） | `window.prompt()` 在**手机浏览器（尤其 WebView/部分 Android）不支持**，弹不出输入框 | 不用 prompt：自制**站内弹窗**（标题+密码 input+确定/取消按钮），`v-if` 控制显隐，手机电脑通用 |
| **表单输入框在手机上溢出容器/弹窗右侧** | `<input>` 是替换元素，**默认固有宽度约 20 字符**，不会像 div 自动撑满，窄屏下冲出容器 | 相关输入框强制 **`width:100%`**（全局 `box-sizing:border-box` 已含 padding）；并排行改 `flex-direction:column` 上下堆叠；弹窗容器加 `overflow-x:hidden` 兜底 |

## 四、数据 / 统计类

| 错误现象 | 原因 | 解决办法 |
|---|---|---|
| **克制推荐只剩一个大类** | 我把克制算法也改成"贝叶斯收缩"，把小样本克制压没了 | 克制**改回用原始胜率算 lift**（`awr = aw/ag`），别收缩 |
| **部分英雄最优组合为空** | 组合最低场次改到 5，很多英雄不够 | 改成"**≥2场收录，没有则取最优1个**" → 每英雄至少一个组合 |
| **冷门完美小样本排太前**（5场100% > 634场50.9%） | 纯 Wilson 下界对完美小样本也偏高 | **贝叶斯收缩 + Wilson 下界**（`wilson_lower(wins+k·prior, games+k)`）+ **提高最低场次**（出装≥10） |
| **出错时 stats.json 被覆盖** | 重跑不会自动备份 | 重跑前先把旧 `stats.json` 备份一份 |
| **新补丁(16.17)爬取慢**：翻 10000 页旧历史全是上个版本 | 新版本对局都在玩家列表**前几页**，深挖旧页浪费时间 | `MAX_PAGES_PER_PLAYER=30`（只看近期 210 场）+ `DELAY=0.15`，专收新版本近期对局 |
| **切换版本时想预览而不破坏线上** | extract/stats 直接写 `processed/` | 把 `extract.py`+`stats.py` 复制到临时目录（OUT_DIR 随脚本位置走），配好名字表文件，跑完看 `stats.json` 覆盖率再决定切换 |
| **爬虫报 `8000022` / `8000101` / `8000004` / `8000108`**（2026-09-06 新坑） | 平台上线**滑块验证**：查"别人战绩"前必须在客户端过滑块（账号级服务端开关，与 cookie 无关、与 IP 无关） | 用户在 WeGame 点别人战绩→过滑块→再跑爬虫；爬虫已加 `[VERIFY-NEEDED]` 自动停机；`8000101/8000004`=该玩家在本区查不到（跨区匹配玩家，属正常）；`8000108`（2026-09-09 出现）=同理按隐藏玩家记录即可，无害 |
| **多进程爬取触发滑块** | 滑块按"单位时间速率"风控（非总量），高频即触发且**窗口随验证次数递减**（当天从 40 分钟缩到 5 分钟，隔夜冷却恢复 25~40 分钟） | **定档：3 进程 × 0.3s**（约 4.5 req/s，稳定 25~40 分钟/次，105~137 场/分钟）；4 进程 ~5 分钟必触发。每区多进程用 WORKER 分片状态文件（`bfscrawl.py` 支持 `AREA`/`WORKER`/`REQ_FILE`/`SEED_FROM_GAMES` 环境变量，按 hash 均分队列） |
| **凭证寿命短 + 抓包只抓到列表请求** | cookie 高强度下 ~1.5 小时过期（`AUTH-EXPIRED`）；详情页有缓存时点击只产生 GetBattleList 抓包 | **合成凭证**：用 GetBattleList 抓包的 cookie + 旧 GetBattleDetail 的 openid 拼出 `REQ_GetBattleDetail_*_synth.json`；`watch_crawl.py` 监视器弹窗提醒（滑块/凭证/饱和三类停止） |
| **凭证 ~1.5h 必过期，换凭证流程繁琐** | 服务端会话 TTL 固定 ~1.5h（与请求频率关系不大：09:13 凭证活 1h17m、15:48 活 1h32m），平台策略不可调 | 别试图延长凭证；**用一键脚本压缩换凭证时间**：`recap_on.py`（证书+代理+mitmweb 一条命令）→ 点对局 → `recap_off.py`（清理+找新凭证+自动合成+验证三区），30 秒完成一轮；验证通过后**回 AI 会话**，由 AI 用托管后台任务拉起爬虫 |
| **滑块窗口随验证次数递减**（隔夜恢复） | 风控按账号累计验证次数缩短窗口：当天从 25~40 分钟逐轮缩到 5 分钟→1 分钟 | 每轮结束过滑块再拉；**窗口接近零就收工**，隔夜冷却恢复；凭证过期优先换凭证再继续 |
| **爬虫跑着的时候做"探测"会提前触发滑块**（2026-09-10 实测） | 滑块按**单位时间速率**风控：爬虫 2 线 ≈ 2 req/s，此时若再用**同一凭证**跑覆盖度/版本探测（每个探测 ~1.5~2 req/s），总速率接近翻倍 → 20:15 双线同时 `[VERIFY-NEEDED]` 停机（本来凭证能撑到 ~20:30） | **爬虫运行期间不要用同一账号凭证做额外 API 探测**（test_api 自测也一样）；要测量就在**没跑爬虫时**测，或接受"可能提前触发滑块"的代价；探测请求也算风控配额 |
| **以为瓶颈是"去重浪费"，其实是 API 延迟**（2026-09-10 实测） | 实测随机玩家前 6 页对局**未抓率 95~100%**，每个玩家可产 **44~52 场**新局；`bfscrawl` 每请求产出 ~0.86 场新局（已接近最优）；真实吞吐 = 请求延迟主导：每次请求 ~0.95s（网络）+ `DELAY` 0.3s ≈ 1.25s → 2 线 ≈ 1.6 req/s ≈ 80 场/分钟 | 想提速不要改去重（已够快），而是**降 DELAY/加线数/上并发**：DELAY 0.3→0.1 约 +24%；加第 3 线 ≈ +50%（但注意上面那条：速率越高滑块越快触发） |

## 六、git / GitHub 类

| 错误现象 | 原因 | 解决办法 |
|---|---|---|
| push 报 **"Author identity unknown"** | 没设 git 身份 | `git config --global user.name/email` |
| push 报 **"src refspec main does not match any"** | 前一步 commit 失败了(身份未设)，没提交 | 先设身份 → commit → 再 push |
| **.gitignore 不生效**（敏感文件仍被 add） | 注释写在**模式同一行**（`captured/  # 注释`）→ git 把整行当模式 | 注释**单独成行**；用 `git check-ignore` 验证 |
| **已提交过的文件** .gitignore 拦不住 | gitignore 只影响"未追踪"文件 | `git rm --cached <文件>` 解除追踪；或删 `.git` + `git init` 重建 |
| push 报 **"Could not connect to github.com port 443"** | 国内访问 GitHub 不稳定/被墙 | 重试多次 / 挂**代理**(`git config http.proxy`) / **SSH** / 换**手机热点** |
| push 报 **"Failed to connect ... via 127.0.0.1"**（配置了 http.proxy=127.0.0.1:7897 但代理没开） | git 全局代理指向本机端口，代理进程已关 | 单次直连绕过：**`git -c http.proxy= -c https.proxy= push`**（沙箱下需全权限，git-bash 凭据管道 EPERM） |
| push 报 **`schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS`** | Windows git 默认 TLS 后端 **schannel** 有 bug/取不到安全凭据（**能连上，但 TLS 握手失败**） | 换 **OpenSSL 后端**：`git config http.sslBackend openssl`，或每次 `git -c http.sslBackend=openssl push`（git-for-Windows 自带 openssl） |
| push 报 **"could not read Username … No such file or directory"** | 头less 环境里远端**没带 token**、又没法交互输密码 | 推送时把 **PAT 写进 URL**（`https://<token>@github.com/…`），推完立刻 `git remote set-url` 换回干净地址 |
| 敏感文件误 push 到**公开仓库** | GitHub 新仓库默认 Public | **立即设 Private** + 移除 + 换凭证/改密码 |
| 用 **Fine-grained PAT** 找不到 "Repository permissions" | 要先选 **Only select repositories** 并勾选仓库，然后切到 **Repository permissions** 标签；**Contents → Read and write** 才是推送所需 | 只勾 Contents=Read and write 即可；Metadata 会**自动 read-only**，不用管 |
| push 报 **`remote: Write access to repository not granted`(403)** | 你个 Fine-grained 令牌**只授权了某几个仓库**，却去推**别的仓库** | 令牌是**按仓库授权**的；给该仓库**单独建/编辑一个令牌**（Only select repositories 勾它）再推 |
| push 报 **"Failed to connect to github.com port 443"** | 直连被墙（**能走代理**时） | `git config --global http.proxy http://127.0.0.1:7897`（加速器端口）+ `https.proxy` 同；`git config --global --get http.proxy` 验证 |
| push **没让你输入用户名/密码**就成功了 | Windows **Git Credential Manager**（`credential.helper=manager`）**缓存了凭据**（`git:https://github.com`） | 这是**好事**，不是异常；以后 `git push` 自动用，不用每次输令牌。想清：Windows 凭据管理器里删 `git:https://github.com` |
| **`git config` 到底改哪了** | 没带作用域 → 默认 **`--local`**（只改当前仓库 `.git/config`） | 想全电脑生效用 **`--global`**：`git config --global http.proxy …`；想只看/看存哪：`git config --get …` / 打开 `.git/config` |
| **在资源管理器看不到 `.git` 文件夹** | Windows 默认**隐藏**以 `.` 开头的文件夹 | 资源管理器「查看」→ 勾「**隐藏的项目**」；或命令行 `Get-ChildItem -Force`；`.git` 一直存在，只是藏起来了 |
| `cd` 报 **"找不到接受实际参数…"** | **路径里有空格**（如 `Deepseek Harness`）被拆成两个词 | **路径加引号**：`cd "E:\Deepseek Harness\git练习"` |
| `git commit` 报 **"pathspec 'm我的…' did not match"** | 打成了 `commit m"..."`（**少了横杠** `-m`） | 写成 `git commit -m "说明"`（`-m`=message；推荐 `-m` 和引号间加空格） |
| 提交记录里 `origin/main` 显示**红色** | git **默认配色**：远端跟踪分支(`origin/*)`显示红色、本地分支绿色、tag 另一种色 | **只是颜色装饰，不是错误**；`git -c color.ui=false log` 可关颜色 |

## 七、venv / 环境 类

| 错误现象 | 原因 | 解决办法 |
|---|---|---|
| `python -m venv` 建 venv 时报 ensurepip 非零退出 | venv 里 pip 没装好（**本机沙箱拦了临时目录 chmod/write**） | 别死磕 ensurepip；用 **base 解释器的 pip + `--python`** 装：`python -m pip --python <venv>\Scripts\python.exe install -r requirements.txt`；遇到 `Permission denied / pip-unpack 写不了` 把该条命令**提到 full-access 权限**再装 |
| **网站/爬虫依赖混装**（爬虫 venv 里出现 fastapi/uvicorn/pydantic …） | 图省事把两份依赖装进同一个 venv | **各自独立 venv**：网站用 `havoc_guide\.venv`，爬虫用 `wegame-capture\.venv`；把混进去的网站包从爬虫 venv 手动删掉，再验证爬虫仍能 `import curl_cffi, mitmproxy` |

## 八、部署 / 前端框架 类

| 错误现象 | 原因 | 解决办法 |
|---|---|---|
| **上传了新版前端但线上还是旧版** | `scp -r dist root@…:/root/web/dist` 会**再套一层**（变成 `/root/web/dist/dist/…`），服务器读的仍是旧的 `/root/web/dist` | 传**内容**：`scp -r "本地\dist\*" root@…:/root/web/dist/`；顺手 `rm -rf /root/web/dist/dist`；验证线上引用的 `/assets/index-*.js` 文件名是否已变 |
| **AI 流式回复变成"一大段蹦出"** | ① Vue3 **响应式坑**：拿 push 后的**原始对象引用**改 `content` 不触发刷新（模板读的是代理）→ 到最后才整段渲染；② **Nginx 默认缓冲** SSE → 攒成大块 | ① 通过**响应式数组按索引**更新：`msgs.value[msgs.value.length-1].content += …`；② Nginx 给流式 location 加 `proxy_buffering off; gzip off; proxy_read_timeout 3600s;` 并 reload |
| Vite dev 里流式也一大块 | 后端调 DeepSeek 走了**本地代理(7897)**可能被缓冲 | 服务器直连无碍；本地可给 httpx `trust_env=False` 绕过代理直连 api.deepseek.com |
| ⚠️ **重启后站点 502**（2026-09-08 事故） | 给 SQLite 已有表加新列时，只把列写进 `CREATE TABLE IF NOT EXISTS`——**老库表已存在不会重跑建表**，新列缺失；启动时播种公告写新列 → `no such column` → 异常冒到模块顶层 → uvicorn 启动失败，全站 502 | ① 给老表加列**必须写迁移**：`PRAGMA table_info(t)` 查列 + `ALTER TABLE t ADD COLUMN …`；② 启动期的数据播种逻辑**必须 try/except 包住**——数据问题绝不允许把站点带崩；③ 部署后立即 `curl /api/site` 验证（502 就查 `journalctl -u havoc-guide -n 50`） |
| **Vue 模板里点按钮没反应**（更换头像等） | 模板内联写 `document.getElementById(...).click()` 会被编译成 `_ctx.document`（Vue 的 `document` 不在全局白名单）→ `_ctx.document` 是 `undefined` → 点击即 TypeError | 把 `document` 操作放进 **script 的普通函数**（`function clickX(){ document... }`），模板只绑定函数名 `@click="clickX"` |
| **换了头像但页面还是旧图** | 头像文件名固定（`用户ID.png`）+ 同扩展名重传 → 浏览器**缓存**旧 URL 显示旧图 | 文件名加**时间戳**（`用户ID_<ts>.png`）+ 上传时 `os.listdir` 删除该用户旧头像文件（前缀匹配 `用户ID_`），每次上传都是新 URL |

## 记住的通用原则
1. **前端改 `index.html` 别重启**；**改 `webapp.py` 必须重启**。
2. **`.gitignore` 注释单独成行**；上传前 `git check-ignore` / `git add -n` 验证。
3. **敏感/凭证/密码哈希文件绝不 commit**（`.env`、`captured/`、`users.json`）。
4. **冷门小样本要"收缩 + 阈值"一起压**，光收缩不够。
5. **改逻辑后跑 `pytest`**，别靠肉眼。
6. **SQLite 老表加列必须写迁移**（`PRAGMA table_info` + `ALTER TABLE`），启动播种逻辑一律 try 保护——数据问题绝不拖垮站点。
7. **Vue 模板里不要直接写 `document`/`window`**，一律走 script 函数。
8. **爬虫不要用 `Start-Process`/`DETACHED_PROCESS` 脱机子进程**（沙箱会回收；用户终端里弹窗被关同样会回收），一律用**托管后台任务**拉起。
9. **`window.prompt` 手机不弹输入框**，交互一律用站内弹窗。
