## 阶段 2 · 数据获取第一步：用 mitmproxy "探路"
WeGame 是**桌面客户端**，符文只显示图标、悬停才见名字，且**同图标可能不同效果**。所以要弄清"它到底请求什么接口、返回什么数据"。

**做法**：
1. 在工作区建 `wegame-capture\.venv`，装 **mitmproxy**。
   - ⚠️ 沙箱：装包要用 `pip --python <venv>`，且把 pip 的临时目录指到工作区内；被拦时升级权限。
2. 写 `addon.py`（mitmproxy 插件）：捕获到 `GetBattleDetail`/`GetBattleList` 等接口时**自动存响应+请求**，并**只存 KIWI 模式**、记录符文ID。
3. 信任 mitmproxy 的 **CA 证书**（装到"当前用户受信任根证书颁发机构"）→ mitmproxy 才能解密 HTTPS。
4. 系统代理指向 `127.0.0.1:8080`（mitmproxy）→ 用户在 WeGame 里浏览，mitmproxy 抓到流量。
5. 启动 `run_mitmweb.py`（代理8080 / 网页界面8081）。

**发现的核心接口**（`www.wegame.com.cn/api/v1/wegame.pallas.game.LolBattle/`）：
- `GetBattleList` → 返回玩家对战列表，每场带 `game_id`、`game_queue_id`、`champion_id`、`win` 等。
- `GetBattleDetail` → 返回单场详情：`player_details[]` 每用户含 `championId`、`playerAugment1~6`（**海克斯强化符文ID**）、`item0~6`、KDA/金币/伤害/等级、`teamId`、`name` 等；`team_details[]` 有 `teamId`+`win`；`battle_detail` 有 `game_mode`、`game_queue_id`、`game_server_version` 等。

> 这一步的关键成果：**搞清了接口、拿到了结构化对局数据、发现了符文ID(playerAugment1-6)**。

## 阶段 3 · 关键突破：不用代理了，直接调接口
试过"抓到的请求原样重放" → **失败 `8025004`**。原因：WeGame 网关检查**浏览器 TLS/JA3 指纹** + 需要**登录 cookie**。

**正解**（写入爬虫）：
```python
from curl_cffi import requests as creq
_client = creq.Session(impersonate='chrome124')     # 伪装成 Chrome（TLS/HTTP2 指纹）
_client.cookies.update(COOKIES)                      # cookie 用 dict 传（pt2gguin/uin/tgp_biz_ticket/pkey/tgp_id…）
_client.headers.update({'trpc-caller':'wegame.pallas.web.LolBattle',   # 只补这俩自定义头
                        'referer':'https://www.wegame.com.cn/helper/lol/index.html'})
# 让 impersonate 自己设置浏览器默认头（user-agent/sec-ch-ua/accept…），不要手动塞整套头！
```
- 直接 POST `GetBattleList`/`GetBattleDetail` → `error_code=0` ✅
- **这就是"不需要代理/证书"的根本原因**：直连 + 伪装指纹 + 登录cookie 就能调接口。

## 阶段 4 · BFS 玩家图谱爬虫（放大数据）
每个游戏里有 10 个玩家的 `openid`（base64 的ID）。**用一个玩家的 `openid` 作为 `id` 去调 `GetBattleList`，就能拿到 TA 的对战列表。** → 从已知玩家出发扩展新玩家 = **指数级覆盖**。

`bfscrawl.py`（BFS爬虫）逻辑：
1. 从 `captured\REQ_GetBattleDetail_*.json` **最新**那份读 cookie/token（`load_auth` 用 `files[-1]`）。
2. `seen_players` 从已有数据 + 种子，队列 = list(seen_players)。
3. 对每个玩家：`GetBattleList` 按 `offset` 分页（`{"id":玩家openid,"count":7,"offset":...}`），**只留 `queue==2400`** 的 `game_id`，跳过已见过的。
4. 对每个新 `game_id` 调 `GetBattleDetail`（`{"id":OWNER_ID,"game_id":...}`），只存 `game_mode=="KIWI"`；从里面挖出新玩家 openid 加入队列。
5. 跳过隐藏玩家（`error_code==8000021`），限速 `time.sleep(DELAY)`。
6. 参数：`MAX_GAMES`（对局预算）、`MAX_PLAYERS`、`MAX_PAGES_PER_PLAYER`（每玩家翻几页）、`DELAY`。
   - 早期用 **10页**；后改为 **10000**（等于"页数上限"，抓满该玩家全部历史，效率更高）。

**为什么"抓满页数"效率更高**：只抓10页只能拿到近期对局（很多已重复）；抓满能挖出**更老的、还没抓过的对局**，每个玩家贡献更多新对局，扩展更少新玩家就能拿到更多数据（近饱和阶段尤其有效）。

## 阶段 5 · 数据清洗与统计

### `extract.py`（原始JSON → 结构化）
- 遍历 `data\detail_*.json`，只处理 `KIWI`，按 `game_id` 去重。
- 每个玩家 → 记录：`game_id`、`version`、`start_time`、`duration`、`champion_id`、`player_name`、`level`、`augments`（playerAugment1-6 非空）、`items`（item0-6非空）、`kills`/`assists`/`deaths`、`gold`、`score`、`damage`、`team_id`、`win`（由 `team_details[teamId].win` 得出）、`ally_champs`、`enemy_champs`。
- 输出 `processed\records.jsonl`（每行一个玩家记录）+ `processed\meta.json`。

### `metadata.py`（ID→名字/头像）
- 用 **Riot Data Dragon**（`ddragon.leagueoflegends.com/cdn/{ver}/data/zh_CN/champion.json` / `item.json`）拿英雄/装备**中文名**；`champion_names.json`、`item_names.json`。
- `augment_names.json` = 见阶段6（符文名）。

### `stats.py`（统计引擎，核心）
- **英雄总览**：每英雄 {wins, games, wr, wilson}，按 wilson 排序。`wilson_lower(k,n)`（置信度下界）。
- **单个符文胜率**：`WR(R|X)=含R对局胜率`；用 `wilson` 排序；最小样本 `MIN_GAME`。
- **组合胜率**：精确符文集合（**≥2个才算组合**，单个不算），最小样本 ≥2，按 `wr` 排序。
- **协同（搭配增益）**：两两 pair，`lift = WR(A&B) − 英雄整体wr`；最小样本 ≥5；按 **wilson** 排序（避免小样本100%顶到最前）。
- **克制推荐**：按**敌方阵容标签**统计，先每标签找最优符文，再**按符文去重**（一个符文一行，列出它克制的敌方类型），**只保留正增益**。
- **出装**：按 `item0-3`（核心三件套）聚合，按场次/胜率排序。
- **排除 A 类随机符文**（`质变`/`潘朵拉`）——它们的结果随机、胜率虚高（给棱彩），不应作为推荐。

## 阶段 6 · 符文名（数据难点，已解决）
对局里只有**整数ID**，没名字。尝试过：
- WeGame 网络接口：符号目录**不在接口**（客户端本地打包）→ 拿不到。
- 游戏 WAD 提取 / CommunityDragon：WAD难解析 + **腾讯pallas ID 与游戏资源ID 可能对不上** → 放弃。

**正解**：你在 `E:\英雄联盟符文id\kiwi\augments.json` 找到了**从游戏文件提取的符文表**（222个：`id / name / cn(中文) / en / rarity(品质) / desc(描述) / ver`）。
- 校验：我们数据里 210 个 augment ID **全部命中 Kiwi 表（缺=0）** → **同一套编号**。
- 构建 `augment_names.json`：`id → {name(中文), quality(白银/黄金/棱彩), desc, en}`。
- **你悬停抽查确认 → 映射正确**。

## 阶段 7 · 网站（FastAPI + 前端）

### `webapp.py`（后端）
- 启动时加载 `stats.json` + 元数据。
- 接口：
  - `/` → 前端首页。
  - `/api/champions` → 英雄排行（含头像、best3 符文+品质）。
  - `/api/champion/{id}` → 英雄详情：`augments_by_quality`（白银/黄金/棱彩 每档最多15）、`combos`（≥2、附名字+品质、最多20）、`synergy`（附名字+品质、最多15）、`builds`（最多15）、`counters`（去重、附品质、最多15）、`quality`。
  - `/_?_` 过滤"质变/潘朵拉"；每个符文补 `name`/`quality`。
- 头像：DDragon CDN 图。

### `static/index.html`（前端，单页）
- **首页**：搜索 + 排序（Wilson/胜率/场次，正倒序）+ 排行榜（头像、胜率、前3符文+品质徽标）。点行进详情。
- **英雄详情**：整体胜率、最优单个符文（分品质档）、最优符文组合、搭配增益、核心出装、克制推荐；每个板块**小字说明**；每个符文带**品质徽标**（白银灰/黄金金/棱彩紫）。
- **详见页**：各板块标题**右上角 `›` 小箭头** → 进入**该板块完整列表页**（`openSection`，含返回按钮、显示全部、有"共 N 条"）。
- 交互：`renderHome` / `openChamp` / `openSection` / `sec` / `itemsList` / `toggleM`（后两者早期内联展开，已改用详见页）等。
