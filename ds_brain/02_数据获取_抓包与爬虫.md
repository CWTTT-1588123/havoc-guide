# 数据获取 —— 抓包与爬虫（详细）

> 这是本项目最核心也最难的部分：**怎么拿到海克斯大乱斗的真实对局数据**。

---

## 一、为什么需要抓到 WeGame 的接口
- WeGame 是**桌面客户端**，我无法直接看它请求什么。
- 符文在界面只显示**图标**、悬停才见名字；且**同图标可能不同效果**。
- 所以第一步是**"探路"**：拦下 WeGame 的 HTTPS 流量，看清接口和数据结构。

---

## 二、探路：mitmproxy 中间人抓包（一次性）
### 安装 mitmproxy
- 在工作区建虚拟环境：`E:\Deepseek Harness\wegame-capture\.venv`
- 安装：`python -m pip --python <venv> install mitmproxy`
  - ⚠️ 沙箱会拦 pip 写入系统临时目录 → 把 `TMP/TEMP/PIP_CACHE_DIR` 指到工作区；仍被拦则**升级权限重试**。

### 让 mitmproxy 能解密 HTTPS
1. 生成 CA 证书：mitmproxy 首次运行会在 `.mitmproxy\mitmproxy-ca-cert.cer` 生成。
2. **信任证书**到"当前用户 → 受信任的根证书颁发机构"（用 `.NET X509Store` 或 certutil；PowerShell `Remove-Item` 对被信任根证书会提示"UI not allowed"，需用 `.NET X509Store.Add/Remove`）。
3. **系统代理设为 `127.0.0.1:8080`**（mitmproxy），绕过列表 `localhost;127.0.0.1;<local>`。
4. 启动：`run_mitmweb.py`（用 `python -m mitmproxy.tools.main`，因为被 `mitmweb.exe` 被系统应用程序控制策略拦截，只能走python模块）。

### 抓包插件 `addon.py`
- 命中 `GetBattleDetail`（且 `game_mode=="KIWI"`）→ 存响应 `GetBattleDetail_<ts>.json` + 请求 `REQ_GetBattleDetail_<ts>.json`。
- 命中 `GetBattleList` / `GetChampion` / 可能是符文目录的接口 → 也存/记录。
- 记录符文图标 URL 里的 string-id 到 `rune_ids.txt`。

### 关键：用户配合
- 你在 WeGame 里**浏览**（历史→海克斯大乱斗→点开对局详情）→ 触发请求 → mitmproxy 抓到。

## 三、发现的接口（数据来自这里）
Base：`https://www.wegame.com.cn/api/v1/wegame.pallas.game.LolBattle/`

- **`GetBattleList`**：POST，body `{account_type:2, area:1, id:<openid>, count:7, filter:"", offset:<n>, from_src:"lol_helper"}`
  - 返回 `battles[]`：`game_id`、`game_start_time`、`game_queue_id`、`champion_id`、`win`、`kills/deaths/assists` 等。
- **`GetBattleDetail`**：POST，body `{account_type:2, area:1, id:<OWNER_ID>, game_id:<game_id>, from_src:"lol_helper"}`
  - `battle_detail`：`game_mode`(=KIWI)、`game_queue_id`(=2400)、`game_id`、`game_start_time`、`game_time_played`、`game_server_version`、`team_details[]`(teamId+win)。
  - `player_details[]`：`championId`、`playerAugment1~6`(**海克斯符文ID**)、`item0~6`、`championsKilled/assists/numDeaths`、`goldEarned`、`gameScore`、`physicalDamageToChampions`+`magicDamageToChampions`、`level`、`teamId`、`name`、`openid` 等。

> **关键字段**：`playerAugment1~6` = 该玩家本局带的6个强化符文ID（整数）；`teamId`→`team_details[].win` = 该玩家胜负。

## 四、关键突破：直连调接口（不用代理了）
用原请求重放 → **`8025004`**（鉴权失败）。原因：网关校验**浏览器TLS/JA3指纹** + **登录cookie**。

**正解**（`curl_cffi` 伪装 Chrome）：
```python
from curl_cffi import requests as creq
_client = creq.Session(impersonate='chrome124')
_client.cookies.update(COOKIES)   # 用 dict 传 cookie（pt2gguin/uin/tgp_biz_ticket/pkey/tgp_id…）
_client.headers.update({'trpc-caller':'wegame.pallas.web.LolBattle','referer':'https://www.wegame.com.cn/helper/lol/index.html'})
```
⚠️ **坑**：之前失败是因为**手动塞了整套浏览器头**(user-agent/sec-ch-ua/accept…)，导致 impersonate 的指纹没生效。**让 impersonate 自己设默认头，只补 `trpc-caller`+`referer`，cookie 走 `cookies` 参数** → `error_code=0`。

**结论**：爬虫**直连接口**，用 `curl_cffi`(伪装指纹) + 登录cookie。**不需要代理、不需要 mitmproxy 证书**。

## 五、BFS 玩家图谱爬虫（`bfscrawl.py`，主爬虫）
**核心思想**：每场有 10 个玩家 `openid`。**用玩家 `openid` 作为 `GetBattleList` 的 `id`**，能拿到 TA 的对战列表 → 发现新玩家 → **指数级覆盖**。

### 流程
1. `load_auth()`：读 `captured\REQ_GetBattleDetail_*.json` **最新**一份（`files[-1]`）拿 cookie + OWNER_ID（作为"查看者"id 调 `GetBattleDetail`）。
2. `seen_players` = 已有数据里的玩家 openid + OWNER_ID；队列 = list(seen_players)。
3. `scan_seen_games()` 建"已抓对局"去重集合：**从文件名提取** `detail_[a<区>_]<game_id>.json` → game_id（2026-09-10 优化，9.8 万文件 **0.4s**；旧实现逐个 `json.load` 要 28s~4min，冷缓存更慢）；文件名不规范的少数文件才回退解析 JSON。去重集合必须完整，否则会重复下载已有对局、白白消耗请求配额（配额=风控/滑块窗口）。
4. 每玩家：`GetBattleList`(offset 0,7,14…) → 只留 `queue==2400` 的 `game_id`；跳过已见。
5. 每个新 `game_id`：`GetBattleDetail` → 只存 `game_mode=="KIWI"`；提取新玩家 openid 加队列。
6. 跳过隐藏玩家（`error_code==8000021`）；限速 `time.sleep(DELAY)`。
7. 停止：`new_games>=MAX_GAMES` 或 `processed>=MAX_PLAYERS` 或队列空。

### 参数
| 参数 | 含义 | 当前（16.17 双线策略） |
|---|---|---|
| `MAX_GAMES` | 本run新增对局预算 | 50000 |
| `MAX_PLAYERS` | 本run处理玩家上限 | 100000 |
| `MAX_PAGES_PER_PLAYER` | 每玩家翻几页（新版对局都在列表前几页，深挖旧页浪费） | **30** |
| `DELAY` | 每请求间隔(秒)；双线×0.3s 是实测安全档（约 4.5 req/s） | 0.3 |
| `AREA` / `WORKER` | 大区 / 多进程分片（状态文件名加 `_a<区>_w<n>`） | 1 / 1、2 |

> **为什么不抓满页数**：新版本对局集中在玩家列表前几页，翻到 10000 页全是上个版本的旧对局 → 只翻 30 页（近期 ~210 场）效率最高。

### 启动（AI 用托管后台任务跑，唯一入口）
```
# run_in_background=true，workdir=E:\Deepseek Harness\wegame-capture
& "E:\Deepseek Harness\wegame-capture\start_crawl.ps1" -Worker 1
& "E:\Deepseek Harness\wegame-capture\start_crawl.ps1" -Worker 2
```
> 直连，不需要代理。⚠️ `start_crawl.ps1` 含中文注释，必须存 **UTF-8 with BOM**（PS 5.1 无 BOM 会按 GBK 读→解析失败，见 08）。

### `crawler.py`（单历史爬虫）
早期版本：只爬某个账号的历史（先 `GetBattleList` 分页拿 `game_id`，再 `GetBattleDetail`）。`bfscrawl.py` 是升级版（BFS）。二者 `load_auth` 都读 `files[-1]`（最新凭证）。

## 六、凭证过期处理（`8025009`）
- 爬虫读到 `error_code!=0`（如 `8025009`）会停止并提示。
- **重新抓 cookie**：临时启用 mitmproxy（信任证书 + 系统代理8080 + `run_mitmweb.py`），你在 WeGame 里浏览点一场，mitmproxy 抓到**新** `REQ_GetBattleDetail`（含新cookie），爬虫读最新那份即可。
- **抓完记得清掉**：关系统代理（`ProxyEnable=0`）、删 mitmproxy 证书、停 mitmweb。

---

## 七、失败/边界处理
- **非 KIWI**：`GetBattleList` 里 `game_queue_id!=2400` 的跳过；`GetBattleDetail` 里 `game_mode!="KIWI"` 的不存。
- **隐藏战绩**：`GetBattleList` 返回 `error_code==8000021` → 记入 `hidden_players.json` 并跳过。
- **限速**：`DELAY` 分片；避免封号。
- **只存 KIWI**：确保数据全是海克斯大乱斗。
