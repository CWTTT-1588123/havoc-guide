## 五、系统层注意事项（重要）
- **系统代理应关闭**（`ProxyEnable=0`）。否则上网会被劫持。当前已关闭。
- **mitmproxy CA 证书**：只在"重新抓包"时才临时信任；用完删掉（安全）。当前已删。
- **爬虫直连**，不依赖系统代理/证书。只有当"凭证过期"（爬虫报 `8025009`）时才需要临时抓包刷新 cookie。

### 如何重新抓包（cookie过期时）
1. 信任 mitmproxy CA：用 `.NET X509Store` 加 `mitmproxy-ca-cert.cer` 到"当前用户受信根"。
2. 系统代理设为 `127.0.0.1:8080`（绕过列表 `localhost;127.0.0.1;<local>`）。
3. 启动 `run_mitmweb.py`（`python -m mitmproxy.tools.main`，因 mitmweb.exe 被系统策略拦）。
4. 你在 WeGame 浏览点一场 → 抓到新 `REQ_GetBattleDetail`。
5. **抓完清理**：系统代理 `ProxyEnable=0`、删mitmproxy证书、停mitmweb。
6. 爬虫读最新 `REQ` 即可。

## 六、常见问题
- **详细错误+解决**：见 **`08_常见错误与解决.md`**（部署/登录/前端/统计/测试/git 全部坑，**新错误务必追加那里**）。
- **爬虫报 `8025004`**：没伪装指纹/没带对 cookie。确认用 `curl_cffi` + `impersonate='chrome124'` + `cookies` dict + 只补 `trpc-caller`/`referer`。
- **爬虫报 `8025009`**：登录凭证过期 → 重新抓包刷新 cookie（见上）。
- **爬虫报 `8000021`**：对方隐藏战绩 → 正常跳过。
- **点英雄进不去**：多数是前端 JS 报错。用 `node -e "new Function(script)"` 检查语法；用错误栈定位。
- **statistics 里有的英雄无数据/空板块**：样本不足（如某个符文<最小样本），属正常。
