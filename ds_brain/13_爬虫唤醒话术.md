## 一键唤醒话术（直接复制整段）

> 我是海克斯大乱斗攻略站项目的维护者，现在要继续 WeGame 数据爬取，请按既定流程接管。
>
> 工作区：`E:\Deepseek Harness`。网站（havoc_guide，FastAPI+Vue）与爬虫（wegame-capture，curl_cffi 伪装 Chrome 直连 WeGame 接口）分离，各自独立 venv：`wegame-capture\.venv`（爬虫）与 `havoc_guide\.venv`（网站+数据管线）。
>
> 当前策略：只爬艾欧尼亚（AREA=1）双线（WORKER=1/2），PATCH_VERSION=16.17，SEED_FROM_GAMES=0，MAX_PAGES_PER_PLAYER=30，DELAY=0.3，MAX_GAMES=50000，MAX_PLAYERS=100000；凭证取 `wegame-capture\captured\` 下最新 `REQ_GetBattleDetail_*.json`。
>
> 流程：
> 1) 先查状态：读 `crawl_a1_w1.log` / `crawl_a1_w2.log` 尾部 + 数 `data\detail_*.json` 最近 10 分钟新增——`[AUTH-EXPIRED]`=凭证过期、`[VERIFY-NEEDED]`=滑块、无这两行且无 `[done]` 且文件在涨=还在跑。**沙箱里进程枚举不可信**（Get-Process/tasklist 都被拦），只信文件证据。
> 2) 凭证过期 → 让用户在**自己开的 PowerShell** 里跑 `recap_on.py`（自动信任证书+开系统代理+后台起 mitmweb）→ 用户在 WeGame 点开一场海克斯大乱斗对局详情（有滑块就过）→ 跑 `recap_off.py`（自动停 mitmweb+关代理删证书+找新凭证/自动合成+验证三区）。自测返回 8025009=凭证仍无效需再点对局；8000022=需先在客户端过滑块。**recap 脚本不拉爬虫**——拿回新凭证名后由 AI 拉起。
> 3) 拉起爬虫：AI 用**托管后台任务**跑 `start_crawl.ps1`（`run_in_background:true`，workdir=wegame-capture）。默认**双账号四线**（有第二个号时）：账号A `-Worker 1/2`、账号B `-Worker 3/4`，各自带自己的 `-CredFile`；只有一个号就用 `-Worker 1/2`。输出自动重定向到 `crawl_a1_w<n>.log`。**绝不要用 Start-Process/DETACHED 脱机子进程**（沙箱会回收、用户关窗也会回收 → 爬虫静默死）。
> 4) 监控：每条后台任务结束（凭证 ~1.5h 过期 / 滑块 / 达到 MAX_GAMES）会收到任务完成通知；平时看日志尾部：`[progress]` 正常推进，`[hidden] 8000021` 正常跳过，`[err] curl (28) 瞬时超时` 自动恢复无碍。**爬虫运行期间禁止再用同一凭证做探测**（会提前触发滑块）。
> 5) 数据落袋：先备份 `havoc_guide\processed\stats.json` → `PATCH_VERSION=16.17` 用网站 venv 依次跑 `extract.py`、`stats.py` → 让用户 scp `stats.json` 到 `root@8.137.175.107:/root/processed/` 并 `systemctl restart havoc-guide`。
> 6) 已知规律：cookie 服务端 TTL 约 **1.5 小时必过期**（不可调）；滑块窗口随当日验证次数递减（25-40 分钟→5 分钟→1 分钟），**隔夜恢复**；`8000021` 隐藏玩家正常跳过；`8000101/8000004/8000108` 本区查不到属正常；`8025009` 凭证过期；`8000022` 需过滑块。
> 7) 细节与历史坑看 ds_brain：`00_总览`、`02_数据获取`、`05_运行手册`、`08_常见错误`、本文件；每次收工把进度追加到 `ds_brain\ds_done\run_log.jsonl`。

## 拉起爬虫（AI 专用，托管后台任务）

### 配置 A：单账号双线（~80 场/分钟，跑满凭证寿命不需干预）
```
# 两条都要：run_in_background=true，workdir=E:\Deepseek Harness\wegame-capture
& "E:\Deepseek Harness\wegame-capture\start_crawl.ps1" -Worker 1
& "E:\Deepseek Harness\wegame-capture\start_crawl.ps1" -Worker 2
```

### 配置 B：双账号四线（~160 场/分钟；2026-09-10 起支持，**推荐**）
```
# 账号A 两条线（用 A 抓的凭证）；账号B 两条线（用 B 抓的凭证）——每条线都 run_in_background
& "E:\Deepseek Harness\wegame-capture\start_crawl.ps1" -Worker 1 -CredFile "captured\REQ_GetBattleDetail_<A的时间戳>.json"
& "E:\Deepseek Harness\wegame-capture\start_crawl.ps1" -Worker 2 -CredFile "captured\REQ_GetBattleDetail_<A的时间戳>.json"
& "E:\Deepseek Harness\wegame-capture\start_crawl.ps1" -Worker 3 -CredFile "captured\REQ_GetBattleDetail_<B的时间戳>.json"
& "E:\Deepseek Harness\wegame-capture\start_crawl.ps1" -Worker 4 -CredFile "captured\REQ_GetBattleDetail_<B的时间戳>.json"
```
> **为什么能翻倍**：滑块是**账号级**风控（与 IP 无关），每账号仍只跑 2 线 ≈ 1.6 req/s，各自风控窗口不变。
> **3/4 号线首次启动前**需要一份玩家池（否则只有 OWNER_ID 一个种子、起步很慢）——一次性准备：
> `Copy-Item players_seen_a1_w1.json players_seen_a1_w3.json; Copy-Item players_seen_a1_w1.json players_seen_a1_w4.json`
> **注意**：四线各自的状态文件是 `players_seen_a1_w<n>.json` / `visited_a1_w<n>.json`（互不干扰）；游戏去重是全局的（按文件名），不会重复下载。

> `start_crawl.ps1` 自动取最新凭证并设好全部参数（也可 `-CredFile "captured\REQ_xxx.json"` 指定），输出重定向到 `crawl_a1_w<n>.log`。启动日志依次是 `[start]` → `[init] 队列=未抓过的玩家 …` → `[init] seen_games=… 耗时 0.4s` → `[progress]`；若 30 秒内看不到 `[progress]`，再用日志尾部 + 新对局文件数判断死活。
> ⚠️ **爬虫跑着的时候不要再用同一凭证做任何探测**（test_api、覆盖度抽样等）——探测请求计入风控速率，会提前触发滑块（2026-09-10 实测）。

## 用户操作（凭证过期时）

### 单账号（3 步）
```
# 第 1 步（在你自己打开的 PowerShell 里）：
& "E:\Deepseek Harness\wegame-capture\.venv\Scripts\python.exe" "E:\Deepseek Harness\wegame-capture\recap_on.py"
# 第 2 步：去 WeGame 点开一场海克斯大乱斗对局详情（有滑块就过）

# 然后告诉 AI"凭证好了"（把 recap_off 打印的新凭证名发过来），AI 会跑 start_crawl.ps1 拉起双线
```

### 双账号（两个号各抓一次，共 6 步）
```
# —— 账号 A ——

# 在 WeGame 用【账号 A】登录并点开一场对局详情
& "E:\Deepseek Harness\wegame-capture\.venv\Scripts\python.exe" "E:\Deepseek Harness\wegame-capture\recap_off.py"
#   ↑ 记下它打印的 A 凭证名
# —— 账号 B ——
# 在 WeGame 退出账号 A、登录【账号 B】
& "E:\Deepseek Harness\wegame-capture\.venv\Scripts\python.exe" "E:\Deepseek Harness\wegame-capture\recap_on.py"
# 在 WeGame 用【账号 B】点开一场对局详情
& "E:\Deepseek Harness\wegame-capture\.venv\Scripts\python.exe" "E:\Deepseek Harness\wegame-capture\recap_off.py"
#   ↑ 记下它打印的 B 凭证名
# 把两个凭证名都发给 AI → AI 用配置 B 拉起四线
```
> 两个凭证分别有效 ~1.5h；A 抓完到 B 抓完通常只差 2~3 分钟，所以四线基本同时开工、同时收工。

## 关键文件速查
| 文件 | 作用 |
|---|---|
| `wegame-capture\start_crawl.ps1` | **AI 拉起爬虫的唯一入口**（托管后台任务跑；自动取最新凭证+设参数+重定向日志）。⚠️ 含中文注释，**必须存成 UTF-8 with BOM**（PS 5.1 读无 BOM 文件按 GBK 解码会解析失败，见 08） |
| `wegame-capture\bfscrawl.py` | 主爬虫（BFS 玩家图谱；AREA/WORKER/REQ_FILE/SEED_FROM_GAMES/MAX_*/DELAY 环境变量） |
| `wegame-capture\recap_on.py` / `recap_off.py` | **一键换凭证**（用户自己 PowerShell 跑；只抓凭证+验证，不拉爬虫） |
| `wegame-capture\test_api.py` | 凭证自测（自动取最新抓包，测 1/14/17 三区） |
| `wegame-capture\captured\REQ_GetBattleDetail_*.json` | 凭证来源（最新那份；详情缓存时可合成 `_synth.json`） |
| `wegame-capture\crawl_a1_w1.log` / `crawl_a1_w2.log` | 双线日志（**判断状态唯一可靠依据**）；启动顺序 `[start]`→`[init] 队列=未抓过的玩家…`→`[init] seen_games=… 0.4s`→`[progress]` |
| `wegame-capture\players_seen_a1_w<n>.json` / `visited_a1_w<n>.json` | 状态：发现过的玩家 / 已抓过（下轮跳过）的玩家（worker 分片各一份） |
| `havoc_guide\extract.py` / `stats.py` | 数据管线（原始→records.jsonl→stats.json；网站 venv 跑） |
| `havoc_guide\processed\stats.json` | 线上统计数据（scp 到 /root/processed/ 后重启服务） |
